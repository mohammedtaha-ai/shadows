# Local delivery slice 1: real files and the task contract Implementation Plan

> **For agentic workers:** this plan is built by `backend-builder`, one task at a time, from the
> entries B-96, B-99, B-103, B-104 and B-106 in [stages.md](../stages.md). Steps use checkbox
> (`- [ ]`) syntax for tracking. The controller starts the builder; nobody else executes this plan.

**Goal:** The person and the Planner see every file a project's folder really holds, and a task
names its file work and the behavior of each function it builds, which the executor reads through
`task_context`.

**Architecture:** `Code` gains a stored, paged file inventory written by the scan it already runs;
`Plans` gains an optional `TaskContent.contract`, judged by the same pure rules as the rest of a
plan. The HTTP and MCP adapters translate one call each. Harness carries the new instruction text;
Grants names the two new Planner tools. No new service, table owner or composition path.

**Tech Stack:** Rust 1.94+, SQLx 0.9 / SQLite, tokio, `ignore` (the walk), serde, utoipa,
schemars, rmcp, axum.

**Spec:** [section 17.0](../../core/specs/2026-10-01-task-contracts-and-evidence-design.md#170-approved-local-delivery-revision-2026-11-09)
owns behavior ("Repository and ready-made servers", first paragraph only; "The task contract",
without its last paragraph on decisions). Shapes: the
[shared request](../../shared/requests/2026-11-09-local-delivery.md), as amended by its
"Backend answer, slice 1". Order and rulings: the [program](2026-11-09-local-delivery-program.md).

## Global Constraints

- Start at `crates/shadows-core/src/app.rs`; change a rule only in the service that owns it. An
  adapter reads a request, calls one method and shapes the answer.
- A contract (`contract.yaml`) and the code map change in the same commit as their module.
- One build cache: no `CARGO_TARGET_DIR`, no worktree build, no `cargo clean`, no `--release`.
- Run only the tests a task names, by `-p` and test target. Never `cargo test --workspace`.
- Before each commit run the checks of [AGENTS.md](../AGENTS.md) rule 5 (fmt, both clippy runs,
  `architecture` and `codemap`, no `.rs` line over 100 characters).
- New tests are real: a real temporary folder, a real SQLite file, the real router, a real MCP
  client on a real port. No new `fake-acp` test, fake worker or fake server. Agent behavior is
  proven by a live test (`#[ignore = "live: needs API_KEY_MINIMAX"]`).
- A live test reads `API_KEY_MINIMAX` from the environment. Load it from `.env` with this loop,
  never with `. ./.env`, and never print it:
  `while IFS='=' read -r k v || [ -n "$k" ]; do v="${v%$'\r'}"; case "$k" in API_KEY_MINIMAX) export API_KEY_MINIMAX="$v";; esac; done < .env`
- Default page size is 100, maximum 200; order is normalized relative path (spec 17.0).
- `reads` and `writes` remain permission scopes and may contain globs. A contract is not
  permission to expand them (spec 17.0).
- Omitted legacy content serializes exactly as before (spec 17.0): a task with no contract has no
  `contract` key in its JSON, its stored row or its command fingerprint.
- `model.rs` and the pure rule files import nothing from `sqlx`. No free `pub fn`. Ordering is
  explicit. Comments say why, never history.
- Commit with `git add <each file>` and the message `feat(backend): B-<n> <goal>`, ending with the
  `Co-Authored-By` line of the model you run on. Do not push, stash or switch branches.
- Do not touch `web/`. `web/src/api/schema.d.ts` is regenerated by the frontend task that follows.

## Review Focus

1. **A file named `.env` in a tracked folder.** A person expects its name and never its content.
   Pinned by `inventory_lists_every_file_whatever_its_language` (B-96): the serialized page holds
   no `SECRET_CANARY`.
2. **A huge ignored folder (`vendor/`, a Python runtime).** A person expects one line, not 2354.
   Pinned by the same test: `vendor` and `node_modules` are one excluded entry each, with nothing
   under them.
3. **A link or junction leading out of the folder.** A person expects it shown and never entered.
   Pinned by `a_link_out_of_the_folder_is_listed_and_never_entered` (B-96).
4. **The folder changes while someone pages.** A person expects to be told to start again, not a
   mixed list. Pinned by `inventory_pages_in_path_order_and_refuses_a_stale_cursor` (B-96) and by
   the 409 in `the_person_and_the_planner_see_the_same_files` (B-99).
5. **A Planner that pastes a function body into `behavior`.** No rule can detect it. The
   instructions forbid it, and `live_the_planner_writes_a_contract_without_a_function_body`
   (B-106) checks one real answer. Watch for it when trying the slice in the browser.

Produces, in `model.rs` (all `pub`, exported from `lib.rs`, re-exported from

```rust
/// What a listing asks for. Built by an adapter; never deserialized.
#[derive(Debug, Clone)]
pub struct InventoryQuery {
    /// A folder relative to the project's folder; "" for all of it.
    pub prefix: String,
    /// The `next` of the page before this one.
    pub after: Option<String>,
    /// 1 to 200.
    pub limit: u16,
}
// impl Default: prefix "", after None, limit 100.

#[derive(Debug, Clone, Copy, PartialEq, Eq, serde::Serialize, utoipa::ToSchema)]
#[serde(rename_all = "snake_case")]
pub enum InventoryKind { Directory, File, Excluded }

#[derive(Debug, Clone, Copy, PartialEq, Eq, serde::Serialize, utoipa::ToSchema)]
#[serde(rename_all = "snake_case")]
pub enum InventoryState { Missing, Indexing, Ready, Incomplete }

#[derive(Debug, Clone, PartialEq, serde::Serialize, utoipa::ToSchema)]
pub struct InventoryEntry {
    /// Relative to the project's folder, with '/'. A folder has no trailing '/'.
    pub path: String,
    pub kind: InventoryKind,
    /// The name `shadows-index` gives the file's extension; null for any other file.
    #[schema(required)]
    pub language: Option<String>,
    /// `dependencies`, `ignored`, `secret` or `link`; null unless `kind` is `excluded`.
    #[schema(required)]
    pub excluded_reason: Option<String>,
    /// The code index holds at least one tag of this file.
    pub has_symbols: bool,
}

#[derive(Debug, Clone, PartialEq, serde::Serialize, utoipa::ToSchema)]
pub struct InventoryPage {
    pub state: InventoryState,
    /// Moves by one each time a listing changed the stored entries; 0 before the first.
    pub generation: u64,
    pub entries: Vec<InventoryEntry>,
    /// What to pass as `after` for the following page; null on the last.
    #[schema(required)]
    pub next: Option<String>,
    /// When the last listing ended (RFC 3339); null before the first.
    #[schema(required)]
    pub observed_at: Option<String>,
}
```

Produces, in `error.rs`: a fifth variant
`#[error("the file list changed; read it again from the start")] InventoryStale`.

Produces, in `inventory.rs` (`impl Code`):

```rust
pub async fn inventory(
    &self,
    asker: Asker<'_>,
    query: InventoryQuery,
) -> Result<InventoryPage, CodeError>

pub async fn refresh_inventory(&self, asker: Asker<'_>) -> Result<InventoryPage, CodeError>
```

- `inventory` lists the asker's own project only (never a linked one). Called by B-99's two
  adapters. In this order:
  1. `limit` outside 1..=200: `InvalidCommand("limit must be 1 to 200")`.
  2. `prefix` through `Code::inside`, then `Code::path_key`.
  3. `Projects::get(asker.home())`; an unknown project is its `ProjectsError` (404 over HTTP).
  4. `touch(asker.home())`.
  5. No stored directory, or `folder_exists` false: `{ Missing, 0, [], None, None }`.
  6. In one read snapshot: the scan row and the page. No scan row: `{ Indexing, 0, [], None, None }`.
  7. `after`: the text `"<generation>:<path_key>"`, split at the first ':'. Not that shape, or a
     key outside `prefix`: `InvalidCommand("the cursor is not one this listing gave")`. A
     generation other than the stored one: `CodeError::InventoryStale`.
  8. `limit + 1` rows after the cursor's key; `next` is `"<generation>:<key of the last entry
     answered>"` when the extra row exists. `state` is `Incomplete` when the scan row says so,
     else `Ready`.
- `refresh_inventory` lists the folder again now, then answers
  `inventory(asker, InventoryQuery::default())`. After `Projects::get` and `touch`: when the
  project has a worker, it sends `Job::Refresh(reply)` and awaits the reply for at most 30 s
  (`code.refresh_timeout` logged past it, and the page is answered as it stands); with no worker
  (before `Code::start`) it calls `self.scan(project)` on the caller's task. It carries no
  `CommandId`: the inventory is a copy derived from the files, as the index is.

Produces, private to the crate:

- `scan.rs`: `fn walker(dir: &Path, hidden: bool) -> ignore::WalkBuilder` holding the settings
  both walks share (`parents(false)`, `git_global(false)`, `require_git(false)`,
  `follow_links(false)`, `hidden(hidden)`); `walk` builds on `walker(dir, true)` and behaves as
  today. `scan_project` calls `self.record_inventory(project, &dir)` after its `index_file` loop
  and before its delete step, unless `stop` ended the loop; a failure is logged
  `code.inventory_failed` and never fails the scan.
- `inventory.rs`: `struct Listed { rows: Vec<InventoryRow>, incomplete: bool }`,
  `fn listed(dir: &Path) -> Listed` (blocking) and
  `async fn record_inventory(&self, project: &ProjectId, dir: &Path)` on `Code`
  (`spawn_blocking(listed)`, skipped when the folder vanished, then `write_inventory` with
  `Storage::now()`).
- `store/inventory.rs`: `pub(crate) struct InventoryRow { path_key, path, kind: &'static str,
  excluded_reason: Option<&'static str> }` and, on `CodeStore`:
  - `write_inventory(&self, project, rows: Vec<InventoryRow>, incomplete: bool, observed_at: &str)
    -> Result<(), StorageError>`: one `write_txn`. Nothing for a removed project
    (`require_live_in`, as `write_code_file`). Inserts new keys and updates changed rows; deletes
    the keys not in `rows` only when `incomplete` is false. The generation is 1 for the first
    write, else the stored one plus 1 when any row was inserted, updated or deleted, else
    unchanged. Upserts the scan row.
  - `inventory_page(&self, project, prefix_key: &str, after_key: Option<&str>, limit: i64)
    -> Result<Option<(i64, bool, String, Vec<(String, InventoryEntry)>)>, StorageError>`: one
    read snapshot; `None` without a scan row; else generation, incomplete, observed_at, and at
    most `limit` `(path_key, entry)` rows `ORDER BY path_key`. "Under the prefix" is the byte
    range `key/` to `key0`, as `code_outline`; `has_symbols` is `EXISTS` over `code_tag`;
    `language` is filled by the caller from `language_for`.
  - `Code::delete_code_index_in` (`store/mod.rs`) also deletes the project's rows of both new
    tables, so a project's removal still succeeds.
- `watch.rs`: `Job::Refresh(oneshot::Sender<()>)`: a scan, then the reply.

The listing rule (`listed`), which the signature does not determine:

1. `seen` = the path keys of every entry `walker(dir, false)` yields below `dir`, its
   `filter_entry` refusing a folder named `.git` or one `Code::never_walked` names. A walk error
   sets `incomplete`.
2. From `dir`, for each folder listed as `directory`, read its children with `std::fs::read_dir`
   (an error sets `incomplete`). For each child, the first rule that matches decides:
   - named `.git`: not listed;
   - a folder `never_walked` names: `excluded`, `dependencies`, not entered;
   - a secret name: `excluded`, `secret`. A secret name, compared in lower case, is `.env`, or
     starts with `.env.` and does not end with `.example`, or ends with `.pem`, `.key`, `.p12` or
     `.pfx`, or is `id_rsa` or `id_ed25519`;
   - `file_type().is_symlink()` (a link or a junction): `excluded`, `link`, not entered;
   - its key is not in `seen`: `excluded`, `ignored`, not entered;
   - a folder: `directory`, entered; a regular file: `file`; anything else: not listed.
3. A name that is not UTF-8 is not listed.

The migration, exactly:

```sql
-- The file inventory is derived from the folder, as the index is: it can be
-- deleted and rebuilt, and carries no command or journal row.

CREATE TABLE code_inventory (
    project_id      TEXT NOT NULL REFERENCES project(id) ON DELETE RESTRICT,
    path_key        TEXT NOT NULL,          -- `path`, lowercased on Windows
    path            TEXT NOT NULL,          -- relative to the project folder, '/'
    kind            TEXT NOT NULL CHECK (kind IN ('directory','file','excluded')),
    excluded_reason TEXT NULL,
    PRIMARY KEY (project_id, path_key),
    CHECK ((kind = 'excluded') = (excluded_reason IS NOT NULL))
);

CREATE TABLE code_inventory_scan (
    project_id  TEXT PRIMARY KEY REFERENCES project(id) ON DELETE RESTRICT,
    generation  INTEGER NOT NULL CHECK (generation >= 1),
    incomplete  INTEGER NOT NULL CHECK (incomplete IN (0, 1)),
    observed_at TEXT NOT NULL
);
```

`ContractRules::problems` gains, after Task 3's rows, in this order:

| When | Message |
|---|---|
| an output id is blank or occurs twice | ``T{n} contract: missing or repeated output id `{id}` `` |

- A task whose work is a function or a class has symbols. A configuration or scaffolding task names its files and has none: do not invent a function for it.
- produces: what other tasks may rely on, each with an id (o1), either symbol_id or artifact (a file path), and the acceptance items that prove it.
- uses: what this task relies on. For another task's output: {"source": {"kind": "task", "target": {"kind": "local", "task": 1}, "output": "o1"}, "purpose": "..."}. For code the project already holds: {"source": {"kind": "existing", "path": "...", "symbol": "..."}, "purpose": "..."}. Never copy a producer's signature into the task that uses it: Shadows gives the executor the producer's contract.
- A task that uses another task's output also links to it (needs, or completes_after); the plan is not approved without that link.
- steps, invariants, forbidden: the order of work when it matters, what must stay true, and what must not be changed.
```

  them.
- If the contract cannot be built as written, stop and say why, with the evidence.
```
