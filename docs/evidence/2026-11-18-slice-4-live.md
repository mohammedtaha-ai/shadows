## The failure

```text
panicked at crates\shadows\tests\fixtures\listening.rs:164:5:
task_question failed: GRANT_SCOPE: not found: no such plan version or task in this project,
or no running attempt holds this grant's task
```

The test starts a real executor on T1, then asks `task_question` itself on the executor's
grant, retrying every 2 s for up to two minutes until gopls answers the code half. The
refusal says no running attempt holds the grant's task: the attempt had ended before the
test's own question got a code answer. The likely cause is a race in the test: the live
executor finished T1 while gopls was still starting, and an ended attempt's grant is refused
by design. Not confirmed with a second run.

## B-166: the cause, confirmed, and two passing runs

Date: 2026-11-18, same branch and environment. A probe printing each `task_question` answer
and the attempt's state showed the code half answering, for every try, "no running language
server reads `.go` files (gopls: idle)" until the executor committed T1 (about 18 s and 26 s
in two runs), after which the next try was refused with GRANT_SCOPE. gopls was not slow to
start: it never started. `AppCore::start` starts the code service (`Codebase::start`), but the
test app is assembled without it, so `touch` only records the use and no worker runs. The
retry loop then raced the executor's turn and always lost. The cause is in the test, not the
product.

The fix (`crates/shadows/tests/task_questions_live.rs`): `gopls_warm` starts the code service
as the daemon does (`name_index: false`) and asks `code_lsp` `findReferences` on Hello until
gopls answers, before the attempt starts; the test then asks `task_question` once, at once,
and asserts the code half is answered. Every other assertion is unchanged.
