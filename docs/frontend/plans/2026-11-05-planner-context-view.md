# Planner Context View Plan (Planner context slice 3)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Status:** draft, 2026-11-05. Not reviewed.

**Goal:** In a Planner conversation, Mohammed sees where the conversation is anchored and changes
or clears it, starts a conversation anchored at a part or an outcome, sees on each turn whether
the planning context was heard, opens what it carried, and asks for it to be sent again.

**Architecture:**
- **One backend task (B-59):** each operation's `invocation` gains `planning_context`:
  `"heard"`, `"prepared"` or `null`. `Harness` owns both the invocation row and the context
  record, so it reads them together. The conversation then knows every turn's state from the
  operations list it already loads, with no request per turn.
- **The web half** uses the routes slices 1 and 2 shipped: `GET/PUT /api/threads/{id}/anchor`,
  `GET /api/operations/{id}/context`, `POST /api/threads/{id}/context/resend`.
- The anchor chip lives in the conversation header beside the stage chip. The record opens in the
  conversation's side panel, where the plan panel opens today.
- A part or outcome page links to the draft with `?anchor=part:<id>` or `?anchor=outcome:<id>`.
  The draft's first send sets the anchor after the thread exists and before the first turn starts,
  so the first turn carries it.

**Spec:** `docs/backend/specs/2026-11-04-planner-context-design.md` §4.1, §4.3 ("On request"),
§4.4, §6 item 3.
**Shared requests:** `docs/shared/requests/2026-11-04-planning-context-routes.md` and
`docs/shared/requests/2026-11-04-planning-context-resend.md` (both accepted);
`docs/shared/requests/2026-11-05-turn-context-state.md` (B-59, asked).

## Global Constraints

- One job per file; no `helpers`/`utils`. Each changed module updates its `contract.yaml`, and
  each new file gets its row in `docs/frontend/codebase/README.md`, in the same commit.
- Types come from `web/src/api/schema.d.ts`, generated by `npm run gen:api`; never hand-edited.
- Every mutation sends a `command_id` kept in an `Attempt` (`web/src/api/command-id.ts`) until it
  succeeds or its content changes.
- Nothing here shows for an AYLUL conversation (`harness === 'aylul'`), as the stage chip does
  today.
- `design` may not import `conversation` (the architecture table): the part and outcome pages
  reach the draft by a router link only.
- Rust lines ≤ 100 characters. `api/openapi.json` changes only with B-59.
- Builders run only their own tests (`npx vitest run <file>`, `cargo test -p <crate> --test
  <name>`); CI runs the full gate.

## Review Focus

1. **The anchored part is removed.** The chip says "Anchored part was removed" and offers Clear;
   it does not fail or show a raw id only. (F-87: `shows_a_removed_anchor`.)
2. **A turn from before slice 1, or a command sent alone** (`/compact`). It has no record: the
   turn shows nothing, and opening is not offered. (F-89: `a_turn_without_a_record_shows_nothing`.)
3. **The draft's anchor call fails after the thread exists.** The person lands in the thread with
   the error and the text, as a failed first turn does today; a retry does not make a second
   thread. (F-88: `a_failed_anchor_keeps_the_thread_and_the_text`.)
4. **Send again while a turn runs.** The button answers at once ("The next turn carries it
   again"); the running turn is unchanged. (F-87: `send_again_says_the_next_turn_carries_it`.)
5. **A long record** (over 8 000 tokens, with cuts). The panel scrolls; cuts and the over-budget
   figure are listed above the text, not lost below it. (F-89: `lists_cuts_before_the_text`.)

**Interfaces:**

- `ContextMark` shows under a turn's user message:
  - `"heard"`: "Planning context · heard";
  - `"prepared"`: "Planning context · not confirmed" (the turn did not end normally);
  - `null`: nothing.
  - Clicking opens the panel.
- `ContextRecordPanel({ operationId, onClose })` shows, in this order:
  - heard or not confirmed;
  - the sizes: index, detail and over-budget tokens;
  - the cuts, one per line;
  - the sources, one per line: kind, id, version;
  - the text, in a scrolled block.
- The panel replaces the plan panel when opened, and the other way round, as the background tasks
  panel does today.
